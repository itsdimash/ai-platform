# AI-платформа Kerneu Group — рабочая папка проекта

Здесь собрано всё, что наработано по внутренней AI-платформе: архитектура,
дизайн-макет, презентации для руководства и каталог готовых промпт-шаблонов.
Платформа независима от ERP — ERP лишь одна из интеграций.

## Структура папки

```
ai-platform/
├── README.md                          — этот файл
├── backend/                           — рабочий скелет FastAPI-сервиса
│   ├── app/
│   │   ├── main.py                    — точка входа
│   │   ├── config.py                  — настройки (.env)
│   │   ├── auth.py                    — JWT, общий секрет с ERP
│   │   ├── adapters/                  — GPT / Claude / Gemini под общим интерфейсом
│   │   ├── classifier/                — определение task_type
│   │   ├── router/                    — конфиг + логика выбора модели
│   │   ├── db_query/                  — whitelist + SQL-валидатор + executor (read-only)
│   │   ├── models/                    — SQLAlchemy: логи, история чатов
│   │   ├── db/                        — подключения к БД (сервис + read-only ERP)
│   │   └── routers/                   — /v1/chat, /v1/sessions
│   ├── alembic/                       — миграции
│   ├── pyproject.toml, Dockerfile, docker-compose.yml, .env.example
│   └── (протестировано: py_compile, TestClient, 11 сценариев SQL-валидатора)
├── prompts/                           — каталог готовых промпт-шаблонов
│   ├── tender_analysis.md             — анализ тендерных спецификаций
│   └── tender_spec_excel.md           — генерация техспецификации в Excel
├── design/
│   └── ai-erp-panel.jsx               — дизайн-макет чат-панели AI внутри ERP
└── presentations/
    ├── Корпоративная AI-платформа.pptx        — общая презентация идеи
    └── AI Router - мозг платформы.pptx        — презентация "мозга" (роутер+БД)
```

Есть также `ai-platform-backend.zip` — тот же `backend/`, упакованный одним архивом, удобно для загрузки в новый git-репозиторий одной командой.

## Архитектура — коротко

```
Запрос → Классификатор (дешёвая модель) → Роутер (config: task_type → модель)
       → GPT / Claude / Gemini → Ответ + логирование
```

- **Классификатор + роутер** — "мозг" платформы, без ML на старте, конфиг-based.
- **db_query** — безопасный read-only доступ к БД ERP (26 таблиц
  проанализированы, whitelist по ролям pm/warehouse/accountant/
  commercial_director/admin, row-level фильтрация, sqlglot-валидатор,
  read-only пользователь PostgreSQL).
- **История чатов** — входит в MVP.
- **Промпт-шаблоны** — готовятся отдельно (см. `prompts/`), не дублируем эту
  работу в роутере.
- **Деплой** — отдельный git-репозиторий, отдельный Docker-сервис рядом с
  ERP-бэкендом на том же сервере, связь через общую БД (read-only) и общий
  JWT-секрет для авторизации.

## Каталог промпт-шаблонов — как это работает в UI

Для задач с готовым промпт-шаблоном, требующим файл (как оба промпта в
`prompts/`), в интерфейсе платформы — **отдельная кнопка-шаблон** (quick
action), а не свободный ввод текста:

```
Пользователь жмёт кнопку "Анализ тендерной спецификации"
        ↓
Загружает файл / вставляет текст
        ↓
Промпт уже привязан к кнопке — классификатор и роутер не нужны,
модель и промпт заранее заданы для этого шаблона
        ↓
Ответ (таблица / JSON / заполненный файл)
```

Это отдельный путь от общего "мозга" (классификатор+роутер) — шаблонные
кнопки обходят классификацию, потому что тип задачи уже известен из выбора
пользователя.

### Текущие шаблоны

| Шаблон | Файл | Нужен веб-поиск | Нужна работа с файлами |
|---|---|---|---|
| Анализ тендерных спецификаций | `prompts/tender_analysis.md` | да | нет (ввод текста) |
| Техспецификация для Excel | `prompts/tender_spec_excel.md` | да | да (шаблон .xlsx) |

Оба промпта уже рабочие сами по себе — их можно использовать прямо в
обычном чате (claude.ai / ChatGPT / Gemini с включённым веб-поиском и
файлами) без всякой платформы. Появление платформы просто уберёт ручной шаг
копирования текста между тендерным документом и чатом.

## backend/ — что уже проверено, а что нет

Проверено в песочнице (без реальных ключей и без Postgres):
- все файлы компилируются (`py_compile`)
- приложение поднимается, все роуты (`/v1/chat`, `/v1/sessions`,
  `/v1/sessions/{id}/messages`, `/health`) регистрируются и отвечают
- SQL-валидатор прогнан на 11 сценариях (хорошие запросы, DELETE,
  SQL-инъекция через `;`, запрещённые функции, чужие колонки, JOIN без
  квалификации, row-level для pm) — по ходу тестирования нашёлся и
  исправлен баг в whitelist-конфиге (`cost_price` не был в базовом списке
  `columns`)

Не проверено (нужны реальные условия):
- живые вызовы к OpenAI/Anthropic/Gemini API
- Alembic autogenerate и реальная миграция (нужна живая PostgreSQL)
- read-only подключение к настоящей БД ERP
